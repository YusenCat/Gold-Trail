## 开始游戏

1. 主机安装 **Node.js 24 或更高版本**。
2. 下载本仓库并保留目录结构。Windows 双击 **`启动游戏.cmd`**，启动窗口请保持打开。
3. 浏览器自动打开驿站大厅，选择对战方式，然后按页面提示开始。

没有自动打开浏览器时，访问 [本机游戏大厅](http://127.0.0.1:4173)。无需执行 `npm install`，项目没有第三方运行依赖。

也可在项目目录运行 `npm start`。macOS / Linux 运行 `node apps/server/server.ts`，再手动打开同一地址。端口默认 4173，可通过 `PORT` 环境变量修改。

| 模式 | 玩家操作方式 |
| --- | --- |
| 本地人机 | 选择走私者或官兵，控制该阵营的两名角色，另一阵营由人机操作 |
| 同屏对局 | 在同一设备上轮流操作四名角色 |
| 局域网 2 人 | 每人控制一个阵营的两名角色 |
| 局域网 4 人 | 每人控制一名角色，双方各两人组成 2 对 2 |

一局始终有四名角色。人机适合熟悉规则，策略与数值仍会随真人试玩继续调整。

## 桌上怎么赢

- **走私者**从金矿取得碎金，送到边境黑市兑换；**官兵**可以稽查走私者，并将碎金运到墨尔根兑换。兑换增加阵营声望。
- 每名角色每回合掷行动骰，获得 **2–4 点行动点**，用于移动、采矿、补给或购买装备；卡牌、事件和道路遭遇会改变局势。
- **竞速局**：先达到 50 声望的阵营获胜。
- **火并局**：进行 30 轮后比较声望，同分平局。

详细规则见游戏内“新手入门”和 [数字版规则书](docs/RULEBOOK_V1.md)。

完整规则由同一规范生成，包含全部地图连接、行动费用、粮草结算、收缴顺序和 39 张卡牌正文。游戏内卡牌文字与规则 API 使用当前规则数据，插画仅作美术；本地 Word / PDF 说明书同步导出，原始材料保留在 `docs/legacy-rules/`。版本变化见 [版本记录](CHANGELOG.md)。

## 回合提示与手机操作

对局上方的“驿路传令”会说明当前需要谁行动，以及下一步可以做什么。当前回合角色与响应、分箱或受控移动的决策者可能不同，请以传令提示为准。提示按钮只带你前往操作区，不会自动执行动作；暂停、断线和等待同伴时也会说明原因。隐藏行前提示不会隐藏关键回合与响应信息。

手机底部提供“地图、行动／回应决策、手牌、局势”四个快捷入口。手牌可横向滑动，地图可放大后点击亮圈规划路线，弹窗内确认操作。响应按钮、快捷入口和表单针对触控调整了尺寸。

## 和朋友联机

1. 主机双击 `启动游戏.cmd`，在大厅选择与朋友处于同一网络的主机地址。
2. 选择“局域网对战”，填写昵称，选择 2 / 4 人及胜负方式，创建房间。
3. 复制邀请链接给朋友。朋友只需要浏览器，在同一局域网打开链接即可；也可以先打开主机地址，再输入六位房间码加入。
4. 全员选择席位并准备，满员在线且全部准备后，由房主点击“全员出发”。成员或席位变化后需重新准备。
5. 行棋和状态会自动同步。队友可查看彼此手牌，只能操作自己的角色；响应、秘密分箱和受控移动由实际决策者处理。敌方手牌、秘密箱数和牌库顺序不会发给无权查看的玩家。
6. 结算后可以“再开一局”，保留席位、取消准备，并显示上局战报。

大厅和房间都可以切换邀请地址，启动窗口也会列出网卡地址。多网卡主机可以运行 `node tools/start-game.mjs --address=192.168.1.20` 预选本机 IPv4 地址。

此版本支持局域网游玩，尚未提供互联网匹配或公网中继。主机需保持运行。首次启动时允许 Windows 防火墙的专用网络访问；朋友打不开时，检查是否处于同一网络、地址和端口是否正确、主机服务是否运行，以及 Wi-Fi 是否启用了访客隔离。

其他设备无法访问主机的本地人机对局和本地存档。主机可在大厅切换模式，各自进度独立保存。

## 存档、断线与恢复

**3.0.4 规则升级提示**：当前执行规则为 1.2.0，矿洞密图和混淆视听的效果已修订。旧规则命名存档会明确拒绝读取；旧本地自动恢复会另存备份，旧房间文件也保留，但不会静默套用新规则。需要完成旧局时，请先使用 3.0.3；升级前备份 `data/`，新版本请新建对局。

**本地对局**：通过“保存行程”创建命名存档，可选择读取；同名时先确认覆盖。文件保存在 `data/saves/`。

**联机对局**：每步操作自动保留在 `data/rooms/<房间编号>/`。房主还可以“保存行程”建立命名快照，先“暂停对局”再“读取存档”，恢复后点击“继续征程”。

成员约 20 秒未发送心跳后，对局暂停并保留席位，不会自动跳过回合。短暂断线、刷新或主机服务重启后，使用**原浏览器、原主机地址**回来；全员在线后由房主继续。服务重启恢复的对局先保持暂停。手机进入后台可能暂停连接，回到页面会尝试重连，必要时点击“重新同步”。

不要清除浏览器数据或随意切换主机地址，否则无法自动找回原身份。开局后暂不支持换人或迁移房主。关闭房间不删除主机上的存档文件。

存档目录由程序自动创建，不随仓库发布。升级或分享游戏时，可以自行备份 `data/`。

## 最小可玩包

```text
启动游戏.cmd            Windows 统一启动入口
package.json            版本与启动命令
apps/server/            HTTP 服务、本地对局、联机房间和存档模块
apps/web/               共享前端、样式及运行用图片
packages/rules/src/     游戏规则和人机策略
content/                地图、卡牌与平衡数据
docs/RULEBOOK_V1.md      游戏内规则书
tools/start-game.mjs     启动服务、检测端口与生成访问地址
tools/start-game.ps1     Windows Node.js 检测入口
```

还包含 `README.md`、`.gitignore` 和 `.gitattributes`。目录结构不能随意改变；卡牌 PNG 和界面 WebP 是运行资源，需要保留。

`.gitignore` 按最小可玩包筛选发布内容。测试、开发文档、参考 PDF / Word、美术 PNG 原稿、旧版地图图片、兼容启动入口、`tmp/`、`output/`、个人存档及依赖缓存保留在开发者本地，不进入发布包。因此发布包只提供 `npm start` 和 `npm run dev`；开发验收脚本不包含在内。

## 验证范围

3.0.0 在 Windows / Node.js 24 环境验证了规则与服务端测试、地图交互、手机宽度布局、真实 CMD 启动、本地人机与存档，以及两个独立浏览器程序的 2 人竞速和 4 人火并联机。联机验收包含自动同步、重复请求、刷新重连、断线暂停、存档读取、服务重启恢复与再开一局。

自动验收使用本机多个浏览器和主机局域网地址；不同设备上的 Wi-Fi、防火墙与手机后台行为仍取决于实际网络环境。
